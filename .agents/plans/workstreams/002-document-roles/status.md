# 문서 역할 분리 — 상태

> 배경과 완료 조건은 `README.md`, 단계와 검증 방법은 `plan.md`에 있습니다.
> 여기는 지금 어디까지 왔고 다음이 무엇인지만 다룹니다.

## 작업 위치

| 항목 | 값 |
| --- | --- |
| 작업 위치 | `workstream/002-document-roles` |
| 기준 브랜치 | `main` |
| 반영 대상 브랜치 | `main` |
| 원격 작업 흔적 | 남기지 않음 — push하지 않습니다 |

계획 커밋도 작업 브랜치에 두었습니다. 사용자가 `main`을 건드리지 않는 조건으로
진행을 요청했기 때문입니다. `workstreams.md`의 기본 절차와 다른 점이며, 그
이유는 `decisions.md`에 있습니다.

## 현재 단계

**검토와 반영을 기다리고 있습니다.** `plan.md`의 1~10단계를 마쳤고, 남은 것은
11단계(마무리)뿐입니다.

`main`에 아직 반영하지 않았습니다. 반영과 아카이브는 사용자 확인을 받고
합니다 — 그것이 이번 검토에서 새로 정한 규칙이고, 이 워크스트림 자신에게도
그대로 적용합니다.

## 최근 완료한 것

- 이 저장소의 운영 문서와 배포 골격을 새 구조로 옮겼습니다.
- 검사기가 새 규격의 필수 문서를 보고, 이전 구조를 만나면 무엇이 어디로
  나뉘었는지 알려 줍니다. 시험은 34개가 통과합니다.
- 세팅 워크스트림 골격을 넷으로 나누고 `APPLY.md`, README 두 벌, 시험 기록을
  맞췄습니다. 버전은 `0.2.0`입니다.
- 1차 검토 결과를 반영했습니다. 아카이브에 사용자 허락을 두고 반영·검증 뒤로
  순서를 옮겼으며, `plan.md` 생성 조건과 문서 읽는 시점, 대작업 판단 기준을
  다시 썼습니다. 그 규칙에 맞춰 이 워크스트림도 활성 상태로 되돌렸습니다.
- 2차 검토에서 나온 종료 절차의 모순 셋을 고쳤습니다. 세팅 문서에 남아 있던
  옛 종료 순서를 없애고, PR 방식이 검증 전에 브랜치를 지우지 않게 했으며,
  완료 흐름과 취소 흐름을 나눴습니다. 보호된 대상 브랜치에서 최종 기록을
  직접 커밋할 수 없을 때의 후속 PR도 명시했습니다.
- 3차 검토에서 빠져 있던 두 단계를 넣었습니다. 아카이브 전에 `status.md`를
  완료 또는 취소 상태로 마지막 갱신하고, 이력·아카이브를 바꾼 뒤 커밋하기
  전에 `cairn check`를 다시 돌립니다. 최종 기록이 대상 브랜치에 들어갔는지
  확인하는 단계도 완료·취소 양쪽에 넣었습니다.

## 다음 행동

사용자 검토를 받습니다. 승인이 나면 `main`에 반영하고, 대상 위치에서 결과를
확인한 뒤 `history.md` 기록과 아카이브 이동을 합니다. push는 하지 않습니다.

## 막힌 점과 열린 질문

- 새 구조에서 에이전트가 실제로 문서를 찾아 이어받는지는 아직 시험하지
  않았습니다. `docs/trials/README.md`의 「앞으로 검증할 것」에 남겼습니다.
- 검토에서 새로 정한 아카이브 승인 절차 자체도 아직 시험하지 않았습니다.
