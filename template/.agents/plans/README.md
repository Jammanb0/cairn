# 계획 문서

이 폴더는 제품 목표, 진행 중인 대작업, 완료 기록과 아직 착수하지 않은 아이디어를
서로 섞지 않고 관리하기 위한 문서 모음입니다. 현재 진행 상태를 확인하려면
`workflow.md`를 읽습니다.

## 문서 구조

| 파일 | 역할 |
| --- | --- |
| `workflow.md` | 현재 대작업과 다음 행동을 찾는 시작점 |
| `goal.md` | 제품의 목적·범위·장기 방향 |
| `history.md` | 완료된 대작업의 결과와 보관 위치를 찾는 짧은 색인 |
| `ideas.md` | 아직 착수를 약속하지 않은 기능과 개선 후보 |
| `workstreams/<이름>/README.md` | 대작업의 배경·목표·범위·완료 조건과 문서 안내 |
| `workstreams/<이름>/workflow.md` | 대작업의 현재 상태·진행 흐름·다음 단계·열린 항목 |
| `workstreams/<이름>/design.md` | 필요할 때만 두는 상세 설계·데이터 흐름·검증 근거 |
| `workstreams/<이름>/decisions.md` | 긴 근거를 별도로 보존할 때만 두는 결정 기록 |
| `.agents/archive/workstreams/` | 완료된 대작업의 원문 기록 |

여기서 말하는 대작업(워크스트림)은 여러 날에 걸쳐 이어지고 여러 커밋으로 나뉘는
작업 묶음입니다. 한 번에 끝나는 작업은 워크스트림으로 만들지 않고, `workflow.md`에
적지도 않습니다. 가르는 기준과 나중에 승격하는 방법은 `workflow.md`의 「대작업
관리 흐름」에 있습니다.

## 읽는 순서

- 작업을 이어갈 때는 `workflow.md`에서 관련 대작업을 찾습니다.
- 대작업을 처음 접하면 그 폴더의 `README.md`로 배경과 범위를 이해합니다.
- 실제 작업을 시작할 때는 같은 폴더의 `workflow.md`를 읽습니다.
- 제품 방향을 확인할 때만 `goal.md`를 읽습니다.
- 아직 착수하지 않은 후보는 `ideas.md`에서 찾습니다.

README는 설명을 담당하고 workflow는 변하는 상태를 담당합니다. 같은 상태를 두
파일에 반복해서 적지 않습니다.

현재 워크스트림의 위치는 이 폴더의 `workflow.md`, 완료된 워크스트림의 위치는
`history.md`에서만 관리합니다. 완료된 워크스트림은 폴더 전체를
`.agents/archive/workstreams/`로 옮기며, 아카이브 문서는 후속 워크스트림의
구체 경로를 직접 가지지 않고 이관 사실만 기록합니다.

같은 폴더의 파일은 파일명으로 줄여 쓰고, 다른 폴더의 파일을 가리킬 때는 저장소
루트 기준 경로와 `/`를 사용합니다.

계획 문서에는 코딩 규칙이나 도메인 지식을 다시 기록하지 않습니다. 관련 원본은
저장소 `AGENTS.md`의 문서 안내표를 따릅니다.
