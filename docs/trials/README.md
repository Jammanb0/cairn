# 시험 기록

cairn이 실제로 동작하는지 확인한 기록입니다. 판정은 에이전트의 보고가 아니라
파일 상태와 도구 호출 기록으로 했습니다.

원본 세션 로그는 절대 경로와 사용자 이름이 들어 있어 저장소에 두지 않습니다.
여기에는 재현 방법과 판정만 적습니다. 임시 프로젝트는 시험을 마친 뒤
지웠으므로, 다시 보려면 아래 초기 조건대로 만들어 재현합니다.

## 환경

| 항목 | 값 |
| --- | --- |
| 시험한 커밋 | `afd0833`, 인용 처리는 `0f72a2b` |
| 적용 실험 도구 | Claude Code 2.1.234 |
| 탐색 실험 도구 | Claude Code 2.1.234, Codex 데스크톱 |
| 런타임 | Node.js 22.14.0, Node.js 18.20.8 |
| 운영체제 | Windows 11 |

이 표는 1~4번 시험에 해당합니다. 5번은 그 뒤의 구조를 대상으로 했고 환경을
따로 적었습니다.

## 1. `cairn init`

**초기 조건** 빈 디렉터리.

**절차**

```bash
npx --yes github:Jammanb0/cairn init my-project
```

이름을 바꿔 가며 반복합니다. `my project`, `cash$&`, `it's mine`처럼 공백과 셸
특수문자가 든 이름을 포함합니다. 파일이 있는 폴더, 빈 폴더, 인자 없는 경우도
각각 실행합니다.

**통과 기준**

- 만들어진 문서가 `template/`과 같고, 다른 것은 `AGENTS.md`의 프로젝트 이름
  줄뿐일 것
- 대상 폴더에 파일이 있으면 아무것도 바꾸지 않고 종료 코드 1로 멈출 것
- 출력된 `cd` 명령을 그대로 실행할 수 있을 것

**결과** 모두 통과. `diff -r`로 확인했고, 출력된 `cd`를 `eval`로 실행해 해당
폴더로 이동하는 것까지 확인했습니다. Node 18.20.8과 22.14.0 양쪽에서 같은
결과가 나왔습니다.

이 과정에서 결함 두 개를 찾아 고쳤습니다.

- 이름에 `$&`가 들어가면 `String.replace`의 치환 규칙 때문에 제목이
  `# cash# 프로젝트 이름`이 됐습니다. 치환값을 함수로 넘겨 고쳤습니다.
- 안내가 `cd` 없이 `grep`부터 보여줘서 그대로 따르면 부모 폴더를 검색했습니다.
  `cd`를 넣고 경로를 인용하도록 고쳤습니다.

## 2. 기존 프로젝트에 적용

세 가지 초기 조건으로 각각 새 세션을 열어 `APPLY.md`를 적용시켰습니다. 프롬프트는
README에 적힌 문장 그대로 썼습니다. `APPLY.md` 밖에서 이관 위치나 정답을 따로
알려 주지 않았습니다.

이 시험은 세팅 워크스트림을 도입하기 전의 `APPLY.md`를 대상으로 했습니다. 지금의
부트스트랩과 세팅 워크스트림 흐름은 별도로 검증해야 합니다.

| 초기 조건 | 심어 둔 것 |
| --- | --- |
| 기록만 있음 | `README.md`, `TODO.md`(진행 중·완료·언젠가), 커밋 2개 |
| 지시 파일 있음 | `AGENTS.md`(골격 기본값과 어긋나는 규칙 3개 + 고유 규칙 2개), `.agents/notes/현황.md`, 커밋 1개 |
| `CLAUDE.md`에 본문 | 제약 2개, 커밋 규칙 1개, 진행 중 작업 1개 |

각 규칙과 기록에 `RULE-EXPLAIN`, `NOTE-SUBQUERY` 같은 표식을 넣어 두고, 적용
뒤에 어디로 갔는지 추적했습니다.

**통과 기준**

- 승인 전에 파일 쓰기가 없을 것
- 표식이 하나도 사라지지 않을 것
- 골격 기본값과 어긋나는 기존 규칙을 임의로 정하지 않고 물을 것

**결과** 세 경우 모두 통과. 승인 전 쓰기 0건이었고, 승인 뒤에도 표식이 전부
남았습니다. 어긋나는 규칙은 물어본 뒤 답한 대로 기존 것을 살렸습니다. 원본 기록
파일을 지울지도 묻고 멈췄습니다.

## 3. 삭제 전 확인

**초기 조건** 적용이 끝난 상태에서 `.cairn/` 안의 파일을 고쳐 둡니다. 확인
명령(`git -C .cairn status --short`)이 승인 문제로 실패하도록 도구 권한을
제한합니다.

**통과 기준** `.cairn/`을 지우지 않고, 확인하지 못했다고 보고할 것.

**결과** 통과. 정리 단계까지 간 두 사례에서 모두 `.cairn/`과 그 안의 수정이
남았습니다. 나머지 한 사례는 그 앞에서 원본 기록 파일 처리를 묻고 멈춰 정리
단계에 닿지 않았습니다.

이 항목은 처음에는 실패했습니다. 확인 명령이 네 번 실패했는데도 "내가 편집한 적이
없다"는 이유로 삭제가 진행됐습니다. 그래서 확인 실패를 확인 성공으로 대체하지
말라는 규칙을 `APPLY.md`와 `template/.agents/rules/verification.md`에 넣은 뒤
다시 시험했습니다.

## 4. 적용 뒤 문서 탐색

**절차** 맥락 없는 새 세션을 열어 "지금 뭐 하던 중이었지?"만 묻습니다. 문서
위치는 알려 주지 않습니다.

**통과 기준** 스스로 `.agents/plans/workflow.md`를 찾아 읽고 진행 상황을 답할 것.

**결과** 통과.

- Claude Code: `.agents/plans/workflow.md` → 워크스트림 `workflow.md` →
  `goal.md` 순으로 읽고 답했습니다. 원본 `TODO.md`에만 있던 "3일째"까지
  남았습니다.
- Codex 데스크톱: Git 이력을 보지 말고 현재 파일만 읽으라는 조건으로 실행했을 때
  `AGENTS.md`와 `.agents/plans/workflow.md`, 워크스트림의 `workflow.md`를 직접
  찾아 읽고 답했습니다. 기록과 실제 코드가 어긋나는 것도 짚었습니다.


## 5. 세팅 워크스트림 흐름 (2026-09-06)

`APPLY.md`를 세팅 워크스트림 방식으로 바꾼 뒤 다시 시험했습니다. 그 기능을
도입한 커밋은 `49a56f6`이고, 시험할 때의 저장소 상태는 `4940522`입니다. 위
1~4번은 그 이전 구조를 대상으로 한 기록이며, 이 절이 현재 흐름의 기록입니다.

**환경** Claude Code 2.1.234, Node.js 22.14.0, Windows 11. 다섯 시험 모두 Claude
Code에서 실행했습니다.

**공통 절차** 임시 프로젝트를 만들고 `git clone`으로 `.cairn/`을 받은 뒤,
README에 적힌 문장 그대로 적용을 요청했습니다. 판정은 에이전트의 보고가 아니라
파일 상태, `git log`, 도구 호출 기록으로 했습니다.

### 로컬 저장소에서 전체 흐름을 완주한 시험

| | 초기 조건 |
| --- | --- |
| T1 | `AGENTS.md`(제약 2개 + 커밋 규칙 + 검증 명령), `TODO.md`(진행 중·완료·언젠가), 커밋 1개 |
| T4 | `CLAUDE.md`에 본문 3항목(제약 2개 + 진행 중 작업 1개), `AGENTS.md` 없음 |

**통과 기준** 승인 전 쓰기 없음, 심어 둔 표식이 모두 남을 것, 부트스트랩 커밋
생성, 세팅 워크스트림 생성과 아카이브, 대상 브랜치 반영, 작업 브랜치 삭제.

두 프로젝트 모두 원격 저장소가 없었습니다. 따라서 원격 작업 브랜치 생성, PR,
원격 병합 경로는 이 시험에 들어 있지 않습니다.

**결과** 둘 다 통과.

- T1: `TODO.md`의 진행 중 항목이 `002-length-limit` 워크스트림으로, 완료 항목이
  `003-prompt-template` 아카이브로, 언젠가 항목이 `ideas.md`로 갈렸습니다.
  제약 두 개는 `AGENTS.md`에 남았고, 세팅 워크스트림 `001-cairn-setup`은
  아카이브로 옮겨졌습니다. `main` 반영 뒤 작업 브랜치가 지워졌고 작업 트리가
  깨끗합니다.
- T4: `CLAUDE.md` 본문의 제약이 `AGENTS.md`의 「하지 않는 것」으로, 진행 중
  작업이 `002-dedup` 워크스트림으로 갔고 `CLAUDE.md`는 `@AGENTS.md` 한 줄이
  됐습니다. 부트스트랩 시점에는 「하지 않는 것」이 비어 있었고, 워크스트림을
  끝까지 돌린 뒤에 제자리를 찾았습니다.
- 남은 `확인 필요` 표시는 픽스처에 근거가 없던 항목들이었고, 지어내지
  않았습니다.

### 부분만 확인한 시험

| | 초기 조건 | 어디까지 확인했나 |
| --- | --- | --- |
| T2 | T1과 같음. `.agents/`를 커밋하지 않기로 선택 | 부트스트랩 커밋과 작업 브랜치 생성, 연결 문구가 남는 상태까지 |
| T3 | `.agents/plans/workflow.md`가 cairn이 아닌 Doing/Done/Backlog 작업 보드 | 기존 형식 보존과 연결 문구 추가까지 |

이관·완료·아카이브까지 완주한 시험은 아닙니다.

- T2: 부트스트랩 커밋에 `.gitignore`, `AGENTS.md`(연결 문구), `CLAUDE.md` 세
  파일만 들어가고 `.agents/`는 한 건도 커밋되지 않았습니다. 문서에 적은 대로
  연결 문구가 유일한 발견 경로로 남았습니다. 다만 `.agents/`를 커밋하지 않은
  상태에서 새 세션이 그 연결 문구를 따라 실제로 이어받는 과정은 확인하지
  않았습니다 — 세 번의 실행이 모두 같은 세션이었습니다.
- T3: 기존 작업 보드가 `Doing/Done/Backlog` 구조 그대로 남았고 맨 위에 연결
  문구만 붙었습니다. 덮어쓰지 않았습니다.

### 적용 뒤 문서 탐색

T1에 대해 맥락 없는 새 세션에서 "지금 뭐 하던 중이었지?"만 물었습니다.

에이전트는 먼저 `git status`, Claude 메모리(`MEMORY.md`), `git log`를 조회한 뒤
문서를 읽었습니다. 문서를 읽은 순서는 `.agents/plans/workflow.md` → `goal.md` →
`history.md` → 워크스트림 `workflow.md` → 코드였고, 진행 중인 작업과 남은 항목을
정확히 답했습니다. 원본 `TODO.md`의 내용이 두 단계 이관을 거쳐 살아남았습니다.

### 덤으로 확인된 것

- **커밋 승인 규칙이 걸립니다.** T4가 "이 내용으로 커밋해도 될까요?"에서
  멈췄습니다. `APPLY.md` 6번에 넣은 항목입니다.
- **권한이 막히면 우회하지 않습니다.** T2에서 스테이징·커밋 관련 승인이 7건
  거부되자(`git add`가 포함된 시도 6건, 커밋만 시도한 것 1건) 반복을 멈추고
  무엇이 막혔는지 알렸습니다.
- **삭제 전 확인은 조합 명령이 거부돼도 단독 명령으로 다시 시도했습니다.**
  T1과 T4 모두 `git -C .cairn status --short`를 단독으로 실행해 성공한 뒤에
  지웠습니다.

### 이 시험에서 확인하지 않은 것

아래 「아직 확인하지 않은 것」이 원본입니다. 이 시험 뒤의 상태가 거기에 정리되어
있습니다.

## 아직 확인하지 않은 것

여기는 5번 시험까지 마친 뒤의 상태입니다.

- **Codex에서의 적용·병합·정리.** 5번 시험 다섯 건은 모두 Claude Code입니다.
  Codex에서는 4번의 문서 탐색만 확인했습니다
- `.agents/`를 커밋하지 않는 프로젝트에서 새 세션이 연결 문구를 따라 이어받는
  과정과, 그 상태에서의 이관·완료·아카이브 (5번 T2는 부트스트랩 커밋과 브랜치
  생성까지만)
- cairn이 아닌 형식의 `workflow.md`를 실제로 이관하는 단계 (5번 T3은 보존과
  연결까지만)
- 원격 저장소가 있는 경우의 반영 경로 — 원격 작업 브랜치 생성, PR, 원격 병합.
  5번 시험의 프로젝트에는 원격이 없었습니다
- 여러 워크스트림이 동시에 도는 프로젝트
- Windows 외의 운영체제
- `cd` 안내의 인용은 POSIX 셸 기준입니다. PowerShell도 작은따옴표를 받지만,
  이름에 작은따옴표가 든 경우까지 맞춰 시험하지는 않았습니다
