# 검증 현황 · Verification status

cairn이 실제로 동작하는지 확인한 현재 상태입니다. 판정은 에이전트의 보고가
아니라 파일 상태와 명령 출력으로 했습니다.

**여기는 일지가 아니라 보고서입니다.** 지금 `main`에서 확인된 것과 아직 남아
있는 실패만 적습니다. 해결된 실패의 진행 과정과 지나간 버전의 시험 절차는
Git 이력에 있습니다. 고친 결함은 문서가 아니라 자동 시험으로 고정했습니다.

않는 것을 고정했습니다.

## 에이전트 행동 검증

임시 기존 프로젝트를 만들어 적용부터 이어받기까지 한 흐름을 돌렸습니다. 각
시험은 이 저장소를 모르는 별도 세션이 맡았고, 프롬프트에 정답이나 기대 경로를
넣지 않았습니다.

| 시나리오 | 결과 |
| --- | --- |
| 기존 프로젝트에 적용 | 통과 |
| 맥락 없는 새 세션이 이어받기 | 통과 |
| 진행 중 상태 갱신 | 통과 |
| 허락 없이 아카이브하지 않기 | 통과 |
| 허락한 뒤 마무리와 아카이브 | 통과 |

**적용.** 기존 `AGENTS.md`의 규칙 넷과 `TODO.md`의 기록 셋에 표식을 심어 두고
추적했습니다. 일곱 개가 모두 옮긴 자리에서 나왔고 원본 `TODO.md`도 남았습니다.
골격 기본값과 어긋나게 둔 영어 커밋 규칙이 살아남아, 실제로 커밋 넷이 영어로
작성됐습니다. 적용 뒤 `cairn check`가 문제 0으로 통과했습니다.

**이어받기.** 프로젝트 경로와 "지금 뭐 하던 중이었지?" 한 문장만 주었습니다.
진입점에서 `current.md`, 워크스트림 `README.md`, `status.md` 순으로 읽고 진행
중인 작업과 다음 행동, 막힌 점을 정확히 답했습니다. 운영 절차 문서인
`workstreams.md`는 열여섯 개 파일 중 마지막에 열었습니다 — 평범한 이어받기에
절차부터 읽지 않게 한 규칙이 의도대로 작동했습니다. 원본 `TODO.md`에만 있던
"3일째"가 두 단계 이관을 거쳐 살아남은 것도 확인했습니다.

**상태 갱신.** 작업을 이어서 진행한 뒤 `status.md`의 「직전 완료」가 이전 내용을
밀어내고 교체됐습니다. 지나간 항목이 쌓이지 않았습니다.

**아카이브.** 두 세션이 각각 자기 작업을 끝낸 뒤에도 폴더를 옮기지 않았습니다.
완료 조건과 남은 것을 보여주며 아카이브해도 되는지 물었습니다. 아카이브 폴더는
생성되지 않았습니다.

**마무리.** "확인하고 마무리해서 아카이브까지 해줘"라는 한 문장을 받은 세션이
완료 조건을 스스로 다시 검증하고, `status.md`를 완료 상태로 최종화한 뒤,
`history.md`와 `current.md`를 갱신하고 폴더를 옮기고 검사를 다시 돌렸습니다.
같은 허락을 다시 묻지 않았습니다. 허락이 없던 다른 워크스트림은 완료 조건이
찼는데도 옮기지 않고 제안만 했습니다.

**`plan.md`.** 순서를 미리 정할 필요가 없는 작업에서 두 세션 모두 `plan.md`를
만들지 않았습니다. 생성 기준을 알려 준 적이 없습니다.

## 알려진 제한

여기는 이미 발견한 실패입니다. 쓰다가 실제로 밟을 수 있습니다.

- **PowerShell에서 작은따옴표가 든 폴더 이름.** `cairn init`이 출력하는 `cd`
  안내는 POSIX 셸 기준입니다. `it's mine` 같은 이름을 PowerShell에 그대로 붙여
  넣으면 문자열이 닫히지 않습니다.
- **`current.md`의 이름 대조가 너무 넓습니다.** 파일 전체에서 세 자리
  번호-이름 꼴을 찾습니다. 아카이브로 옮긴 워크스트림을 본문에 언급하거나
  `2026-09-08` 같은 날짜를 적으면 없는 폴더로 잡힙니다. 메시지도 사실과 다릅니다.
- **코드 블록을 백틱 울타리만 인식합니다.** `~~~`나 네 칸 들여쓰기로 적은 예시
  안의 경로를 실재해야 하는 링크로 잡습니다.
- **임시 골격 검사가 이름에 묶여 있습니다.** 골격을 `.cairn` 아닌 경로에 두면
  적용 뒤 남은 참조를 찾는 검사가 아무것도 하지 않습니다.
- **검사 범위가 `.agents/` 안입니다.** 프로젝트의 다른 문서가 `.agents/` 안을
  가리키다 끊어져도 잡지 못합니다. 적용 절차가 기존 기록에 이관처 안내를
  붙이라고 하므로 실제로 생기는 상태입니다.
- **에이전트가 문서의 질문 순서를 항상 지키지는 않습니다.** 작업 위치를
  기본값 없이 묻는 흐름은 독립 세션마다 결과가 달랐습니다. 문서가 행동을
  강제하지 않는다는 것이 이 도구의 성립 조건이므로, 지켜지는 경우가 있다는
  것까지만 말할 수 있습니다.

## 다시 확인하려면

임시 기존 프로젝트를 하나 만들고 아래를 순서대로 돌립니다. 세션마다 새로
시작해야 하고, 프롬프트에 문서 경로나 기대하는 답을 넣지 않아야 합니다.

```text
1  AGENTS.md 와 TODO.md 에 추적용 표식을 심은 프로젝트를 만든다
2  README 에 적힌 문장 그대로 적용을 맡긴다
3  워크스트림을 열고 일부만 진행한다
4  새 세션에 "지금 뭐 하던 중이었지?" 만 묻는다
5  작업을 이어서 진행하고 status.md 를 갱신한다
6  마무리를 맡기고 허락 전에 아카이브하는지 본다
```

판정은 표식이 몇 개 남았는지, 읽은 파일이 무엇인지, 아카이브 폴더가 생겼는지로
합니다.
