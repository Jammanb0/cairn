# cairn

[English](README.en.md)

AI 코딩 에이전트와 일할 때 규칙과 진행 맥락이 흩어지지 않게 하는 문서 골격입니다.

케른(cairn)은 산길에 쌓아 두는 돌탑입니다. 길을 만들어 주지는 않지만, 다음
사람이 — 혹은 다시 온 내가 — 어디까지 왔는지 알 수 있게 합니다.

## 무엇을 해결하나

에이전트와 며칠씩 일하다 보면 두 가지가 반복됩니다.

- 규칙이 흩어집니다. Codex는 `AGENTS.md`를, Claude Code는 `CLAUDE.md`를 읽으니
  같은 규칙을 두 벌 쓰게 되고, 한쪽만 고치면 내용이 갈라집니다.
- 맥락이 사라집니다. 새 세션을 열 때마다 "지금 뭐 하던 중이었지"부터 다시
  설명해야 합니다.

이 골격은 규칙의 원본을 `AGENTS.md` 한 곳에 두고 `CLAUDE.md`는 그것을 가리키게
하며, 진행 상태를 `.agents/plans/workflow.md` 한 곳에서 관리합니다.

## 무엇이 들어 있나

```text
AGENTS.md              항상 적용되는 규칙과 문서 안내표
CLAUDE.md              "@AGENTS.md" 한 줄
.agents/
  rules/
    verification.md    다 됐다고 말하기 전에 확인하는 방법
    communication.md   답변을 쓸 때의 태도
  plans/
    README.md          계획 문서의 구조 설명
    goal.md            목적·범위·하지 않을 것
    workflow.md        지금 무슨 작업 중이고 다음이 무엇인지
    history.md         끝낸 작업의 짧은 색인
    ideas.md           아직 착수를 약속하지 않은 후보
    workstreams/<이름>/  여러 날에 걸치는 작업 하나당 폴더 하나
```

골격은 마크다운 문서뿐입니다. 새 폴더를 만들어 주는 `cairn init` 명령이 하나
있지만 안 써도 됩니다. 복사만 하면 같은 결과입니다.

## 받는 법

### 새로 시작할 때

빈 폴더에서 시작하는 것이라면 한 줄로 골격이 만들어집니다. Node 18 이상과
Git이 필요하고, 따로 설치할 것은 없습니다.

```bash
npx --yes github:Jammanb0/cairn init my-project
```

`my-project/`를 만들고 `AGENTS.md`, `CLAUDE.md`, `.agents/`를 넣습니다. 프로젝트
이름만 채워 넣고, 나머지 `<!-- 채우기: -->` 자리는 그대로 둡니다. 대상 폴더에
이미 파일이 있으면 아무것도 바꾸지 않고 멈춥니다.

여기까지가 골격 생성입니다. 프로젝트별 빈칸은 이어서 채웁니다. 남은 자리는
이렇게 찾습니다.

```bash
cd my-project
grep -rnE "채우기|고르기" AGENTS.md .agents/
```

### 이미 작업 중인 프로젝트에 넣을 때

프로젝트 안에 파일을 얹지 않고, 옆에 폴더 하나로 받습니다. 기존 파일은 하나도
건드리지 않습니다.

```bash
git clone --depth 1 https://github.com/Jammanb0/cairn .cairn
```

적용을 마치기 전에 커밋할 일이 생길 수 있으니 `.cairn/`을 `.gitignore`에
넣어 두면 안전합니다. 적용을 마친 뒤의 정리는 `APPLY.md`의 「정리」를 따릅니다.

## 적용하는 법

여기서 말하는 적용은 이미 작업 중인 프로젝트에 넣는 경우입니다. 새로 시작하는
것이라면 위의 `cairn init`으로 골격이 만들어지므로 이 절은 건너뛰어도 됩니다.

절차는 [`APPLY.md`](APPLY.md)에 있습니다. 에이전트에게 시켜도 되고 직접 읽고
따라 해도 됩니다.

에이전트에게 시킬 때:

```text
.cairn/APPLY.md를 읽고 이 프로젝트에 적용해줘.
기존 규칙과 기록은 보존하고, 지시 파일 변경안은 적용 전에 보여줘.
```

직접 할 때는 `APPLY.md`를 순서대로 따라갑니다. 기존 문서를 살리면서 옮겨 담고
연결하는 단계가 핵심입니다.

적용이 끝나면 `.cairn/` 폴더는 지웁니다.

## 기존 프로젝트에 넣을 때 주의할 것

**파일을 복사하는 것만으로는 적용이 끝나지 않습니다.** 기존 `AGENTS.md`를
그대로 두고 `.agents/`만 추가하면, 그 폴더를 읽으라는 안내가 없어서 아무도 읽지
않습니다. 파일은 생겼는데 아무 일도 일어나지 않는 상태가 됩니다.

그래서 `APPLY.md`는 복사가 아니라 **옮겨 담고 연결하기**를 절차로 삼습니다.
기존 규칙은 살리고, 어긋나는 항목은 사람이 정하도록 짚어서 물어봅니다.

## 무엇을 바꿔 써도 되나

`AGENTS.md`의 다음 부분은 기본값입니다. 팀 사정에 맞게 바꿔도 됩니다.

- 답변 언어
- 작업 전 승인 범위
- 커밋과 푸시 승인 방식, 커밋 메시지 언어와 형식

`verification.md`의 테스트·빌드 명령처럼 프로젝트마다 다른 자리는
`<!-- 채우기: -->`로 비워 두었습니다. 나머지 원칙은 그대로 써도 됩니다.

문서는 한국어로 되어 있습니다. 다른 언어로 쓸 거라면 번역해서 쓰면 됩니다.

## 범위

AI 없이도 쓸 수 있습니다. 마크다운 문서라서 사람이 읽고 직접 관리해도 됩니다.
다만 애초에 AI와 일할 때 규칙과 맥락이 흩어지는 문제를 풀려고 만든 것이고,
그 상황에서 가장 값을 합니다.

특정 도구에 묶여 있지 않습니다. `AGENTS.md`와 `CLAUDE.md`를 읽는 도구라면
무엇이든 됩니다.

## 어디까지 검증했나

Claude Code 2.1.234와 Codex 데스크톱으로 임시 프로젝트를 만들어 확인했습니다.
판정은 에이전트의 보고가 아니라 파일 상태와 도구 호출 기록으로 했습니다. 초기
조건과 통과 기준, 실제 결과는 [`docs/trials/README.md`](docs/trials/README.md)에
있습니다.

확인된 것

- `cairn init`이 `template/`과 같은 문서를 만들고, 파일이 있는 폴더에서는
  아무것도 바꾸지 않고 멈추는 것 (Node 18·22)
- 기존 지시 파일과 기록이 있는 프로젝트에 적용할 때, 승인 전에 쓰지 않고 기존
  규칙을 살리며 어긋나는 항목을 물어보는 것
- 삭제 전 확인이 실패하면 `.cairn/`을 지우지 않고 멈추는 것
- 적용 뒤 새 세션이 `.agents/plans/workflow.md`를 스스로 찾아 읽고 진행 상황을
  답하는 것 (Claude Code와 Codex 양쪽)

아직 확인하지 않은 것

- **Codex에서의 적용과 정리.** Codex에서는 문서 탐색만 확인했습니다
- 여러 워크스트림이 동시에 도는 프로젝트, 이미 다른 문서 체계를 쓰는 프로젝트
- 오래 쓰면서 워크스트림을 완료하고 아카이브로 옮기는 흐름
- Windows 외의 운영체제
